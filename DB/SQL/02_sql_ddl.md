### DATA DEFINITION LANGUAGE (DDL)

> DDL CHANGES **STRUCTURE** — TABLES, COLUMNS, CONSTRAINTS. IT DOES NOT INSERT ROWS BY ITSELF.
>
> COMMON COMMANDS: `CREATE`, `ALTER`, `DROP`

#### CREATE TABLE

> `CREATE TABLE` DEFINES A NEW TABLE — COLUMN NAMES, DATA TYPES, AND RULES (CONSTRAINTS).
>
> EACH COLUMN NEEDS A **TYPE** (`INT`, `VARCHAR`, `DATE`...). ADD **CONSTRAINTS** TO ENFORCE RULES ON DATA.

```sql
-- DEFINE TABLE persons WITH COLUMNS + PRIMARY KEY
CREATE TABLE persons (
    id INT NOT NULL,                    -- NOT NULL = REQUIRED VALUE
    person_name VARCHAR(12) NOT NULL,
    person_dob DATE,                    -- NO NOT NULL = OPTIONAL (CAN BE NULL)
    email VARCHAR(50) NOT NULL,
    phone VARCHAR(15),
    CONSTRAINT person_pk PRIMARY KEY (id)   -- PRIMARY KEY = UNIQUE id PER ROW
);
```

#### ALTER TABLE

> `ALTER TABLE` CHANGES AN **EXISTING** TABLE — ADD, DROP, OR MODIFY COLUMNS (AND CONSTRAINTS IN FULL SYNTAX).
>
> `ADD` — NEW COLUMN. `DROP COLUMN` — REMOVES COLUMN **AND ALL DATA IN IT** (CANNOT UNDO).

```sql
-- 'ALTER TABLE' IS USED TO CHANGE EXISTING TABLE

ALTER TABLE persons
ADD person_role VARCHAR(20)

-- REMOVE A COLUMN (DATA IN THAT COLUMN IS LOST)
ALTER TABLE persons
DROP COLUMN person_role;
```

#### DROP TABLE

> `DROP TABLE` **DELETES THE ENTIRE TABLE** — STRUCTURE + ALL ROWS. GONE FOR GOOD UNLESS YOU HAVE A BACKUP.
>
> USE WITH CARE. WRONG TABLE NAME = BIG MISTAKE.

```sql
-- DELETE TABLE persons COMPLETELY
DROP TABLE persons;
-- WARNING: ALL DATA IN THIS TABLE IS REMOVED
```
